# 聊天页工作区侧栏与抽屉布局设计

## 背景

当前工作区可视化虽然已经具备文件树、文件预览、diff 和下载能力，但它以嵌入式面板的方式塞在聊天内容里，视觉上更像一张卡片，和消息流混在一起，不符合“副工作区”的直觉。

用户希望工作区是一个明确可显隐的区域：

- 顶部和“上下文 / 思考过程”同一行放一个按钮。
- 桌面端是右侧挤压式副工作区。
- 小屏端退化成抽屉。
- 保留现有文件树、预览、diff、下载，不拆成独立管理页。

## 目标

- 工作区有明确的开关入口。
- 打开时聊天区仍然保留在视野里，桌面端不被整块遮住。
- 面板外观像应用内的副工作区，而不是嵌套卡片。
- 关闭/打开不丢失当前搜索、展开、选中文件和预览状态。
- 只调整前端布局，不改后端 API 和工作区数据模型。

## 方案

### 桌面端

`ChatView` 持有一个 `workspaceVisible` 状态。打开后，聊天主区域变成左右两列：

- 左侧是聊天消息和输入框。
- 右侧是工作区副工作区，宽度固定在一个保守区间内，推荐 `clamp(360px, 34vw, 520px)`。

工作区副工作区使用整块独立背景和左侧分割线，尽量不要再包一层“卡片里的卡片”。这样用户会把它理解成页面级侧栏，而不是消息流里的附属模块。

### 移动端

当视口太窄时，右侧副工作区改为抽屉覆盖式展示：

- 默认收起。
- 点击顶部按钮打开。
- 点击遮罩或再次点按钮关闭。
- 抽屉内仍然复用同一个工作区内容组件。

### 状态保留

工作区关闭时只隐藏，不销毁。这样再次打开时还能保留：

- 当前搜索词。
- 树节点展开状态。
- 选中的文件路径。
- 文件 / diff 预览模式。

## 组件边界

### `ChatView.vue`

负责：

- 顶部工具栏按钮的显隐。
- `workspaceVisible` 状态。
- 根据视口选择侧栏布局或抽屉布局。
- 和现有聊天区、输入框、上下文统计、思考过程开关保持同一层级。

### `WorkspaceBrowserPanel.vue`

只负责工作区内容本身：

- 文件树。
- 搜索。
- 文件预览。
- diff 预览。
- 下载入口。

它不再承担“页面壳层”的视觉职责，外层边框、宽度、遮罩和开合动画交给布局壳层处理。

### 轻量壳层

建议新增一个很薄的布局壳层组件，专门处理桌面侧栏和移动抽屉的切换。这样 `ChatView` 不会继续长成一坨模板逻辑。

## 交互细节

- 顶部按钮使用图标按钮，带 tooltip，`aria-pressed` 反映开关状态。
- 只有当前会话存在时才显示或启用该按钮。
- 打开工作区时，聊天区宽度收缩，但 composer 仍然留在聊天列底部。
- 工作区内的刷新、树展开、文件选择、文件和 diff 切换行为保持原样。
- 不新增独立工作区页面，也不新增拖拽式调宽功能，先保持保守实现。

## 非目标

- 不改命令判官和审批流。
- 不重做工作区 API。
- 不把生图、改图这类纯交互工具并入文件系统面板。
- 不把工作区拆成新路由或新管理页。

## 验收标准

- 顶部工具栏能一键显隐工作区。
- 桌面端打开后是右侧挤压式副工作区，而不是聊天里的卡片。
- 小屏端打开后是抽屉覆盖式工作区。
- 文件树、文件预览、diff、下载都还能正常用。
- 关闭工作区后再次打开，之前的浏览状态还在。
